# 醫師值班排班系統 — API 契約（定案版）

> **這份取代了先前的「護理排班系統 — API 規格」。**
> 舊版的一切設定一概作廢：30 支 API、`/api/v1`、Bearer 認證、`scheduler`／`staff` 角色、
> `If-Match` 樂觀鎖、`unitId`、職級 N1–N4、13 區 51 人、`primary`／`support`、
> 必休／希望休兩層、留職停薪、伺服器端分頁——**這些在定案的系統裡都不存在**。
> 看到設計稿裡還有這些東西，就是待修訂項，見 `DESIGN_REVISIONS.md`。

權威來源是 repo 的 `api-contract.yaml`（OpenAPI，42 個操作、52 個 schema）。
本檔是給設計用的摘要，形狀有疑義時以 `api-contract.yaml` 為準。
術語見 `CONTEXT.md`，約束的代碼與預設值見 `CONSTRAINT_DEFAULTS.md`。

## 系統形態

單機、單一使用者、單一 process、單一科部。WPF/WebView2 殼 + Vite SPA，Windows portable。

- Base path：`/api`（**沒有版本號**）
- **沒有認證、沒有角色、沒有多單位。** 不要在畫面上出現「排班者」這類角色標籤
- **沒有 `If-Match`／ETag。** `revision` 只是修改次數計數器，不是併發控制
- **沒有伺服器端分頁。** 33 人一次全帶，篩選在前端做
- 年月一律以 `ym` 字串表示（`2026-09`），日期一律 `YYYY-MM-DD`
- 值班表以**年月**為識別子、一月一份，沒有 `scheduleId`

## 領域規模

| 項目 | 值 |
|---|---|
| 區域 | **5 個**：A、B、C、ICU、總值 |
| 區域類型 | **3 種**：一般病房（A/B/C）、ICU、總值 |
| 人員 | **33 位** |
| 身分 | **10 種**：PGY1、PGY2、R1、R2、R3、R4、R5、R6、打工R、NP |
| 身分組 | **4 組**：`{PGY1,PGY2,R1,打工R}`、`{R2,R3}`、`{R4,R5,R6}`、`{NP}` |
| 每日每區 | **恰好 1 人**（沒有主責／支援） |
| 約束 | **硬 7 條、軟 7 條** |
| 不可排班日 | 每人每月上限 **16 天**，單一層級（硬性） |

### 兩套點數不可混用

- **額度點數 (QuotaPoint)** — 主要計量。平日 1 點、假日 2 點。每個身分有**硬上限**。
  組內公平比較的是**剩餘額度**（上限 − 已排），不是絕對點數，也不是與全體平均的差。
- **公平性點數 (FairnessPoint)** — 實驗性第二套。由「當日與隔日是否為假日」查表決定，
  Type A / Type B 兩張表。**沒有上限**，預設權重 0（停用）。

### 兩種假日不可混用

- **假日 (Holiday)** — 週六、週日、國定假日的總稱。決定額度點數 1 或 2 點。
- **國定假日 (PublicHoliday)** — 只有紅字法定假日，**不含一般週六週日**。
  只用於「連值兩個週六」加分規則。
- **補班日** 視為平日，1 點。

## 畫面 → 端點對照

### SCREEN 01 · 排班主表

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/api/schedules` | 有值班表的月份清單（年月切換器） |
| GET | `/api/schedules/{ym}` | 取單月完整值班表 |
| PATCH | `/api/schedules/{ym}/duties` | 指派或清空一格 |
| POST | `/api/schedules/{ym}/duties/swap` | 對調兩格 |
| POST | `/api/schedules/{ym}/validate` | 重新驗證整份 |
| POST | `/api/schedules/{ym}/publish` | 發布（＝重新發布，會重算月結轉） |
| GET | `/api/schedules/{ym}/export` | 匯出 Excel |
| GET | `/api/schedules/{ym}/violations` | 違規清單 |
| GET | `/api/schedules/{ym}/point-board` | 點數看板 |
| GET | `/api/schedules/{ym}/days/{date}` | 單日詳表（自帶月負載，不需另打點數看板） |
| GET | `/api/schedules/{ym}/vacancies` | 空缺 |
| GET | `/api/schedules/{ym}/candidates` | 某一格的可指派人員建議 |
| GET | `/api/calendars/{year}` | 表頭星期、假日底色 |

**違規只帶 `code` 與 `severity`，不帶 `display`。**
底色／斜紋／外框由前端決定，不再由 API 指定。公平性是組層級分數、指不到格子，**不出現在違規清單**。

**「已發布」不是鎖定。** 已發布的值班表仍可逐格修改，工具列的動作是「重新發布」。

### SCREEN 02 · 區域類型 ＋ 點數規則

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET · PUT | `/api/settings/areas` | 區域與區域類型（整份取代） |
| GET · PUT | `/api/settings/ranks` | 身分與身分組（整份取代） |
| GET · PUT | `/api/settings/point-rules` | **兩套點數**的規則（整份取代） |
| GET · PUT | `/api/settings/monthly-overrides/{ym}` | 當月覆寫（R6 額度上限用） |

`point-rules` 要容納：額度點數（平日 1／假日 2）、**公平性點數 Type A 與 Type B 兩張 4 列查表**
（當日 × 隔日是否假日 → 點數）、「連值兩個週六」的加分點數與天數視窗。
**假日認定不在這裡**，在行事曆。

### SCREEN 03 · 資格矩陣 ＋ 硬／軟約束

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET · PUT | `/api/settings/eligibility-matrix` | 資格矩陣（**10 身分 × 3 區域類型**） |
| GET · PUT | `/api/settings/constraints` | 7 硬 ＋ 7 軟的約束定義 |

資格由案主直接給定，**沒有推導規則**（不要寫「由本級 a ＋ a−1 自動推導」）。
約束收斂成**九個宣告式原語**，每條帶三個維度的 scope：身分、區域類型、日類（平日／假日／國定假日）。
權重 0–100，自動正規化，填 0 停用。代碼與預設值一律照 `CONSTRAINT_DEFAULTS.md`。

### SCREEN 04 · 變體比較

| 方法 | 路徑 | 用途 |
|---|---|---|
| POST | `/api/solver-jobs` | 建立求解工作 |
| GET | `/api/solver-jobs/{jobId}` | 查詢狀態 |
| DELETE | `/api/solver-jobs/{jobId}` | **中止求解** |
| GET | `/api/solver-jobs/{jobId}/stream` | 進度推送（SSE） |
| GET | `/api/solver-jobs/{jobId}/variants` | 變體清單、指標與完整內容 |
| POST | `/api/schedules/{ym}/apply-variant` | 套用變體為草稿 |

規模：5 區 × 30 日 = **150 個指派**，約 **1–15 秒／變體**。硬 7 ／ 軟 6（S7 預設停用）。

**指標定為 4 個**：空缺數、額度點數公平、同區延續、身分區域偏好；
公平性點數為選配第 5 個，停用時不顯示。**空缺數 > 0 是正常結果**——登記過多時求解器回
「空缺最少」的變體而不是整份失敗，要有對應的視覺提示。

每份變體要顯示**立場標籤**（重視公平／重視延續性／平衡）與所用的權重**乘數**（乘在使用者設定上）。
`SolverJob.warnings` 的非阻斷提醒（「上月仍是草稿」「月結轉為空」）要有地方放。

變體回應已帶完整值班清單，**逐格差異由前端就地計算**，不需額外端點。

### SCREEN 05 · 不可排班日登記

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/api/blocked-days/{ym}` | 取單月登記 |
| PUT | `/api/blocked-days/{ym}/{staffId}/{date}` | 登記一格 |
| DELETE | `/api/blocked-days/{ym}/{staffId}/{date}` | 清除一格 |
| GET | `/api/blocked-days/{ym}/feasibility` | **可行性預警** |

**不可排班日獨立於值班表存在**（ADR-0001），路徑不掛在 `/schedules` 底下。
「值班表尚未產生」是正確且必要的狀態。

**只有兩個筆刷：登記／清除。** 「希望休」是雛型發明的，實際只有一層硬性的「絕對不可排班」。
每人月上限 **16 天**。

**沒有登記期、沒有截止日、沒有鎖定。** 單人單機、排班者是唯一權威，求解前一次確認即可。
沒有匯入紙本、沒有匯出 Excel、沒有提醒未登記人員（無通知機制）。

`feasibility` 是兩層的可行性預判：
① 逐日——哪一天哪個區域類型的可用人數不足。**最危險的是總值**（只有 R4~R6 這 13 人能值）。
② 整月——三層巢狀累計的供需（總值／總值＋ICU／全部）；
「一般病房 vs 低年級剩餘供給」吃緊時提示「R2/R3 優先 ICU 會被犧牲」。

### SCREEN 06 · 人員維護

| 方法 | 路徑 | 用途 |
|---|---|---|
| GET | `/api/staff` | 名冊（**一次全帶 33 人，無分頁**） |
| POST | `/api/staff` | 新增 |
| PATCH | `/api/staff/{id}` | 編輯 |
| DELETE | `/api/staff/{id}` | 刪除 |
| PATCH | `/api/staff/{id}/status` | 狀態變更 |

狀態只有 **在職／停用兩態，沒有生效日**。留職停薪未建模。
額度點數上限**屬於身分**（SCREEN 02），不在人員表；當月的值在點數看板。
可值區域類型由資格矩陣推導，**唯讀**。沒有匯入名冊。

### 行事曆（跨畫面）

## 尚未設計：求解進度覆蓋層

求解要 15–45 秒，期間需要進度呈現，但**不能是百分比進度條**——CP-SAT 給不出可信的完成度。
要呈現的是：

- 「正在求第 **2 / 3** 份變體」
- 已耗時 / 上限（`8.4s / 15s`）
- 本份已找到 **n** 個候選解
- 收斂間隙 `gap`（比例 0–1，非百分比；0 = 已證明最佳）——**會跳動、不單調，不可畫成進度條**
- **中止**按鈕（`DELETE /api/solver-jobs/{jobId}`）

## 設計時的紅線

1. **兩套點數（額度／公平性）與兩種假日（假日／國定假日）絕不可混用。**
   標籤上只寫「點數」或「假日」而不指明是哪一個，一律視為錯誤。
2. **不要加**認證、角色標籤、多單位切換器、`If-Match` 樂觀鎖、伺服器端分頁、登記期鎖定。
   單機單人單科部，這些沒有防禦對象，已在需求釐清中明確排除。
3. **不要出現** N1–N4 職級、主責／支援、希望休、留職停薪、13 區 51 人。
4. 違規的**渲染方式由前端決定**，API 只給 `code` 與 `severity`。
5. **參數化優先**：點數權重、額度上限、約束權重、不可排班日上限一律由設定端點提供，
   UI 不得寫死。
