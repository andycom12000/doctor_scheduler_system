# 變體以軟約束權重組合產生，而非列舉次佳解

一次求解產生 3 份變體的方法是：**用三組不同的軟約束權重各求解一次**，
每份變體有具名的立場（重視公平／重視延續性／平衡），並加一條輕量的多樣性約束
防止兩組權重湊巧解出同一份。三份序列執行，每份 15 秒上限。

## Context

案主要求「產生數種 variant 給排班者選擇」，但 CP-SAT 給的是**單一最佳解**，
要生出好幾份得刻意去要。方法決定了變體之間的差異有沒有意義。

## Considered Options

**列舉次佳解。** CP-SAT 支援，但相鄰解通常只差「兩個人對調」——排班者看不出差別，
比較畫面等於白做。

**只加多樣性約束（要求第 N 份與前面至少 k 格不同）。** 保證看得出差異，
但差異是隨機的，說不出「為什麼這份比較好」，排班者無從選起。

**換亂數種子。** 等同列舉次佳解。

## Consequences

- 變體比較畫面的指標（空缺數、額度點數公平、同區延續、身分區域偏好）
  變得可解讀——每個指標的高低對應到那份變體的立場，而不是隨機波動。
- 三份**序列**求解而非平行：多樣性約束需要看到前一份的結果。
  總耗時 45 秒，在本專案的秒級規模下可接受。
- 權重組合是**乘在使用者設定上的乘數**（`Variant.weightProfile` 會回傳），不是替換：
  實際權重 = `GET /settings/constraints` 的權重 × 乘數。使用者把某條設 0 停用，
  任何變體都不會偷偷把它打開；「平衡」變體全部乘 1。乘數表在 `docs/constraint-defaults.md`。
- 具名立場只有三個，所以 `variantCount` 上限 3。若未來要讓排班者自訂立場，
  把乘數表搬進請求即可，不用重新設計。
