# 不可排班日登記獨立於值班表存在

不可排班日登記的路徑是 `/api/blocked-days/{ym}`，**不是** `/api/schedules/{ym}/blocked-days`。
它是自己的聚合根，鍵為年月，不外鍵到 `schedule`。

## Context

登記發生在值班表存在**之前**：排班者為次月收集大家的不可排班日，收齊了才開始排。
設計稿上有「值班表尚未產生」這個明確的狀態，年月切換器也能選到還沒有值班表的月份。
若把登記掛在 `/schedules/{id}/` 底下，那個 `{id}` 在最主要的使用情境下根本組不出來。

## Considered Options

**先建一份空的值班表，再讓登記掛上去。** 被否決：這是為了遷就錯誤的路徑而發明一個空殼物件，
會讓「值班表」這個詞同時指涉「已排好的結果」與「還沒開始排的容器」。
`CONTEXT.md` 把值班表定義成「某個年月的一份排班結果」——空殼不是結果。

## Consequences

- 求解時，值班表**讀取**登記當作輸入（`Forbidden` 原語），兩者是輸入／輸出關係，不是包含關係。
- 「每人最多登記 16 天」因此是**登記期的驗證規則**，不是求解約束——求解器只看到已登記的日子，
  不需要知道 16 這個數字。
- 刪除某個月的值班表不會連帶刪掉該月的登記，這是正確的：登記是人講出來的事實，
  值班表只是根據它排出來的其中一種結果。
